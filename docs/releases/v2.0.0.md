## Overview

This document details the complete modernization of `lmk` from v1.0.0 (June 2019) to v2.0.0 (November 2025). The project was updated from Go 1.12.1 to Go 1.23+, migrated from Travis CI to GitHub Actions, and gained significant new features including a timer/pomodoro mode.

## Executive Summary

### Before (v1.0.0 - June 2019)

- Go 1.12.1 (no modules)
- Travis CI for releases
- `notify-send` with 30-second notification loop
- Required pressing Enter to dismiss
- Linux (amd64) and macOS (amd64) only
- No timer functionality

### After (v2.0.0)

- Go 1.23+ with modules
- GitHub Actions + GoReleaser
- Modal dialogs with always-on-top support
- Automatic dismissal when acknowledged
- Multi-platform: Linux/macOS/Windows on amd64/arm64
- Built-in pomodoro timer mode (`-t` flag)
- Shows execution time and exit codes

### 2. Notification System Overhaul

#### Problem with v1

The original implementation used:
1. `notify-send` (Linux) or `osascript` notifications
2. 30-second loop to repeat notifications
3. Blocking on Enter key to dismiss

**Issues:**

- Notifications disappeared after a few seconds
- Easy to miss if away from keyboard
- Annoying repetition every 30 seconds
- Had to return to terminal to dismiss

#### v2 Solution: Modal Dialogs

**Linux Priority Order:**

1. **yad** (recommended) - Has `--on-top` flag that actually works
2. **zenity** - Fallback, uses `--question` dialog for better focus
3. **kdialog** - KDE environment support
4. **notify-send** - Last resort fallback (v1.0.0 behavior: notification + Enter prompt)

**macOS:**

- `osascript` with `System Events` activation
- Native dialog with proper focus stealing

**Windows:**

- PowerShell with `TopMost` form property
- MessageBox stays on top

### 3. Timer/Pomodoro Mode

#### User Request

> "I want to build poor man pomodoro on CLI"

#### Implementation

Added `-t` / `-timer` flag to run countdown timers without commands:

```go
func runTimer(timerDuration string, message string) {
    duration, err := time.ParseDuration(timerDuration)
    if err != nil {
        log.Fatalf("Invalid timer duration '%s': %v\nExamples: 25m, 1h30m, 90s",
                   timerDuration, err)
    }

    if duration <= 0 {
        log.Fatalf("Timer duration must be positive, got: %s", timerDuration)
    }

    log.Printf("Timer started for %s", duration)
    time.Sleep(duration)

    msg := message
    if msg == "" {
        msg = fmt.Sprintf("⏰ Timer finished!\n\nDuration: %s",
                         formatDuration(duration))
    } else {
        msg = fmt.Sprintf("⏰ %s\n\nDuration: %s",
                         msg, formatDuration(duration))
    }

    showDialog(msg, false)
}
```

#### Usage Examples

```bash
# 25-minute pomodoro
lmk -t 25m -m "Pomodoro done! Time for a break"

# 5-minute break
lmk -t 5m -m "Break over, back to work!"

# Flexible durations
lmk -t 1h30m -m "Deep work session complete"
```


### 4. Enhanced Information Display

#### Exit Code Tracking

```go
func getMessageAndExitCode(err error, cmd []string, duration time.Duration)
    (msg string, exitCode int, isError bool) {

    durationStr := formatDuration(duration)

    if err != nil {
        exitCode = 1
        if exitErr, ok := err.(*exec.ExitError); ok {
            exitCode = exitErr.ExitCode()
        }
        isError = true
        msg = fmt.Sprintf("❌ %s failed!\n\nExit code: %d\nDuration: %s",
                         strings.Join(cmd, " "), exitCode, durationStr)
    } else {
        exitCode = 0
        isError = false
        if *flagMessage != "" {
            msg = *flagMessage
        } else {
            msg = fmt.Sprintf("✅ %s\n\nDuration: %s",
                             fmt.Sprintf(defaultMessage, strings.Join(cmd, " ")),
                             durationStr)
        }
    }

    return
}
```

#### Duration Formatting

```go
func formatDuration(d time.Duration) string {
    if d < time.Minute {
        return fmt.Sprintf("%.1fs", d.Seconds())
    }
    if d < time.Hour {
        return fmt.Sprintf("%dm %ds", int(d.Minutes()), int(d.Seconds())%60)
    }
    return fmt.Sprintf("%dh %dm", int(d.Hours()), int(d.Minutes())%60)
}
```

## Technical Decisions

### 1. Why yad over zenity?

**Considered Options:**
- zenity (GTK standard)
- yad (zenity fork)
- kdialog (KDE)
- notify-send (original)

**Decision:** Prefer yad, fallback to zenity, then kdialog, finally notify-send

**Rationale:**
- `yad` has proper `--on-top` flag that window managers respect
- zenity's `--modal` is inconsistent across window managers
- yad is actively maintained and more feature-rich
- notify-send as last resort ensures lmk works even on minimal systems
- Better to have degraded notification (must press Enter) than no notification at all
- Graceful fallback chain ensures broad compatibility

### 2. Why modal dialogs instead of notifications?

**Problem:** Desktop notifications:
- Disappear after timeout
- Can be missed when away
- No reliable way to make them persistent

**Solution:** Modal dialogs:
- Block until acknowledged
- Stay on top of windows
- Impossible to miss
- Better UX for long-running tasks

### 3. Why -t instead of only -timer?

**User Request:** `-t` is more concise for frequent use

**Decision:** Support both `-t` and `-timer`

**Implementation:**
```go
func init() {
    flag.StringVar(&flagTimer, "t", "", "")
    flag.StringVar(&flagTimer, "timer", "", "")
}
```

Both flags point to same variable, providing flexibility without code duplication.

### 4. Why include timer in v2.0.0?

**Rationale:**
- Natural fit: "notify me when something is done"
- Timer = "notify me when time is done"
- Zero external dependencies needed
- Minimal code addition (~20 LOC)
- High user value for pomodoro workflows

### 5. Version number jump (0.1.0 → 2.0.0)

**Reasoning:**
- Breaking change in behavior (notification → dialog)
- Major feature addition (timer mode)
- Complete modernization (Go 1.12 → 1.23)
- Signals significant project revival

## Lessons Learned

### What Went Well
1. **Zero external dependencies** - Kept project simple and maintainable
2. **Graceful fallbacks** - Works across different Linux environments
3. **Test-first approach** - Caught issues early
4. **Clear user request** - Timer feature was well-specified

### Challenges
1. **Window manager differences** - zenity `--modal` inconsistent
   - Solution: Prefer yad with better `--on-top` support
2. **Dialog dismissal** - Making dialogs truly stay on top
   - Solution: Platform-specific approaches (yad on Linux, System Events on macOS)
3. **Cross-platform testing** - Limited to Linux during development
   - Mitigation: Clear fallback logic, documented testing needed

### Best Practices Established
1. Always prefer specialized dialog tools over notifications
2. Implement graceful fallback chains for Linux tools
3. Use init() for flag aliases (clean pattern)
4. Format durations in human-readable form
5. Show execution time in all notifications
